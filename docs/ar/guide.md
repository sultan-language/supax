# دليل سوباكس

المرجع الكامل: كل أمر وخيار، والاعتماديات، والبرامج، ومساحات العمل، والاختبارات، والمخبأ، والأمان. أما صيغ الملفات فمفصلة في [صيغ الملفات](formats.md).

## الأوامر

| الأمر | بالعربية | ما يفعله |
|---|---|---|
| `supax new <الاسم> [--lib]` | `supax جديد` | ينشئ حزمة في دليل جديد، ومع `--lib` مكتبة (انظر أدناه) |
| `supax init [الاسم] [--lib]` | `supax هيئ` | ينشئ حزمة في الدليل الحالي، و`--lib` كما في `new` |
| `supax add <الاسم>[@<إصدار>]`، أو `<الاسم> --path <مسار>`، أو `<الاسم> --git <رابط> [--tag <وسم>]`، ولكل منها `[--dev]` | `supax أضف` | يضيف اعتمادية إلى `Supax.toml` (إلى `[dev-dependencies]` مع `--dev`) ويحدّث `Supax.lock`، ولا يغيّر شيئا إن فشل. وبلا `@<إصدار>` يأخذ أحدث إصدار في الفهرس |
| `supax remove <الاسم> [--dev]` | `supax احذف` | يحذف اعتمادية (من `[dev-dependencies]` مع `--dev`) ويحدّث `Supax.lock` |
| `supax fetch` | `supax جلب` | يحل الاعتماديات ويجلبها ويكتب `Supax.lock` |
| `supax update [الاسم...]` | `supax حدث` | يعيد حل الاعتماديات متجاهلا التثبيتات، كلها أو المسماة منها |
| `supax tree` | `supax شجرة` | يعرض مخطط الاعتماديات |
| `supax metadata [--output=<ملف>] [--relative]` | `supax بيانات` | يكتب مخطط الحزم الذي يقرؤه المترجم |
| `supax verify` | `supax تحقق` | يتحقق من المخبأ مقابل `Supax.lock` دون شبكة |
| `supax check` | `supax افحص` | يفحص المشروع بالمترجم |
| `supax build` | `supax ابن` | يبني المشروع في `build/bin/` |
| `supax run [--bin <الاسم>] [-- الوسائط]` | `supax شغل` | يبني المشروع ثم يشغّل برنامجا واحدا |
| `supax test [نص]` | `supax اختبر` | يشغّل الاختبارات (الدوال الموسومة `@@اختبار`) عبر `sultanc test`: المكتبة، ثم كل برنامج، ثم كل ملف في `tests/`. ومع `نص` يكتفي بالاختبارات التي يحوي اسمها ذلك النص |
| `supax fmt [--check]` | `supax نسق` | ينسّق مصادر الحزمة بـ `sultanc fmt` (انظر أدناه) |
| `supax install <الاسم>[@<متطلب>]`، أو `--path <دليل>`، أو `--git <رابط> [<الاسم>]` | `supax ثبت` | يبني برامج حزمة بـ `--release` وينسخها إلى `~/.supax/bin` (انظر أدناه) |
| `supax uninstall <الحزمة> [--bin <الاسم>]` | `supax أزل` | يحذف البرامج التي ثبّتها `supax install` لحزمة |
| `supax clean` | `supax نظف` | يحذف الدليل `build/` |
| `supax package [--git <رابط>]` | `supax حزّم` | يفحص هذا الإصدار (شجرة نظيفة، و`[lib]`، وإصدار دلالي، وبلا اعتماديات مسارية) ويطبع مدخله `[[versions]]` ومسار ملفه في فهرس الحزم |
| `supax publish [--git <رابط>]` | `supax انشر` | يجري فحوص `package` ثم يشرح النشر يدويا: موقع السجل غير متاح بعد، فلا يُرفع شيء ([صيغ الملفات](formats.md#إضافة-إصدار)) |
| `supax yank [<الاسم>@]<الإصدار> [--undo] [--index <دليل>]` | `supax اسحب` | يسحب إصدارا (أو يعيده) في نسخة محلية من الفهرس، وبلا اسم: الحزمة في الدليل الحالي ([صيغ الملفات](formats.md#سحب-إصدار)) |
| `supax migrate` | `supax رحّل` | ينقل `[imports-alias]` إلى أسطر `وحدة` في ملفات الجذر (لم يعد المترجم يقرؤه) |
| `supax cache [info \| clean]` | `supax مخبأ` | يعرض مخبأ git (المجلد والمستودعات والنسخ والحجم) أو يحذفه |

| الخيار | ما يفعله |
|---|---|
| `--dev` | مع `add` و`remove`: الجدول `[dev-dependencies]` |
| `--locked` | يفشل إذا احتاج `Supax.lock` إلى تغيير |
| `--offline` | لا يستخدم الشبكة، ويكتفي بما في المخبأ |
| `--frozen` | يجمع `--locked` و`--offline` |
| `--release` | بناء محسّن: يُمرَّر إلى المترجم `-O3`، كملف release في Cargo (`opt-level = 3`). وبدونه لا يُمرَّر شيء، فيعامله المترجم كـ `-O0`: ترجمة أسرع، وكل متغير مقروء في المنقّح |
| `--bin <الاسم>` | يبني هذا البرنامج وحده أو يشغّله |
| `--package <الاسم>`، `-p` | عضو واحد من مساحة العمل |
| `--target <هدف>`، `-t` | منصة الهدف (القائمة: `sultanc targets`)، والمخرج في `build/bin/<هدف>/` |
| `--quiet`، `-q` | بلا أسطر الحالة (يبني، انتهى، يشغّل) |
| `--message-format=human\|short\|json` | صيغة تشخيصات المترجم، تُمرَّر إليه `--diagnostic-format` في `check` و`build` و`run` و`test` و`fmt`. ومع `json` لا يطبع سوباكس أسطر الحالة، فلا يبقى في مجرى الأخطاء إلا JSON المترجم وأخطاء سوباكس نفسه |
| `--color=auto\|always\|never` | تلوين تشخيصات المترجم |
| `--lang=ar\|en` | لغة الرسائل، والافتراضية العربية. ويمكن ضبطها أيضا بالمتغير `SUPAX_LANG` |

يقرأ سوباكس هذه الخيارات في أي موضع قبل `--`، وما بعد `--` يذهب كما هو إلى البرنامج (`run`) أو إلى `sultanc test` (`test`).

## الاعتماديات

<div dir="ltr">

```toml
[package]
name = "app"
version = "0.1.0"

[dependencies]
mathx = "1.2"                                                   # من فهرس الحزم
json  = { git = "https://github.com/someone/sn-json", tag = "v1.2.0" }
log   = { path = "../log" }
```

</div>

تتبع متطلبات الإصدار قواعد Cargo (`"1.2"` تعني `>=1.2.0, <2.0.0`). وفهرس الحزم مستودع git، الافتراضي `https://github.com/sultan-language/index` ويغيّره المتغير `SUPAX_INDEX`، ويشير كل إصدار فيه إلى التزام git وبصمة محتوى.

صيغة الاعتماديات وملف القفل والمخبأ مفصلة في [صيغ الملفات](formats.md).

### اعتماديات الاختبارات: `[dev-dependencies]`

يسرد الجدول `[dev-dependencies]` الحزم التي لا تحتاجها إلا الاختبارات، ومداخله كمداخل `[dependencies]`:

<div dir="ltr">

```toml
[dev-dependencies]
fixtures = { path = "../fixtures" }
```

</div>

- لا يستوردها إلا ملفات `tests/`. أما ملف في `src/` فلا يستطيع، ولو داخل دالة `@@اختبار`، لأن استيراداته جزء من كل بناء.
- تتركها `build` و`check` و`run` و`metadata`، ويضيفها `supax test`.
- تُحل وتُثبَّت في `Supax.lock` كأي اعتمادية. أما `[dev-dependencies]` الخاصة باعتمادية ما فتُتجاهل.
- لا يكون المفتاح نفسه في الجدولين، فالحزمة التي في `[dependencies]` متاحة للاختبارات أصلا.

## البرامج

يمكن أن يضم المشروع أكثر من برنامج:

| الملف | البرنامج | المخرج |
|---|---|---|
| `src/main.sn` | اسم الحزمة | `build/bin/<الحزمة>` |
| `src/bin/<الاسم>.sn` | `<الاسم>` | `build/bin/<الاسم>` |

يبني `supax build` البرامج كلها، ومع `--bin <الاسم>` يبني واحدا. ويشغّل `supax run` البرنامج `src/main.sn`، فإن لم يوجد وكان في المشروع أكثر من برنامج فمرر `--bin`. وعلى ويندوز ينتهي المخرج بـ `.exe`، ولأهداف WebAssembly (`wasm32-wasi` وأخواته) بـ `.wasm`. ومع `--target` يبني `supax run` البرنامج، لكنه لا يشغّله إلا إن كان هذا الجهاز يقدر على ذلك، وإلا ذكر الهدف الذي بُني له الملف.

### المكتبات

ينشئ `supax new <الاسم> --lib` مكتبة بدل البرنامج:

| الملف | محتواه |
|---|---|
| `Supax.toml` | `[lib] path = "src"` |
| `src/<الاسم>.sn` | ملف الجذر، يستورد وحدات المكتبة فيجد `supax test` اختباراتها |
| `src/lib.sn` | دالة عامة واختبار لها |

وتستوردها حزمة أخرى باسم `<الاسم>.lib`.

## التنسيق

يشغّل `supax fmt` الأمر `sultanc fmt` على `src/` و`tests/` و`main.sn` إن كان بجانب `Supax.toml`، ودليل `[lib]` إن كان خارج `src/`. ومع `--check` لا يغيّر شيئا: يسرد الملفات غير المنسقة وينتهي بالرمز 1، وهذا لـ CI. وفي جذر مساحة عمل بلا `[package]` ينسّق كل الأعضاء. ولا يحتاج الاعتماديات، فيعمل دون شبكة ودون `Supax.lock`.

## تثبيت البرامج

يبني `supax install` حزمة بـ `--release` وينسخ برامجها (`src/main.sn` و`src/bin/*.sn`) إلى `~/.supax/bin` (أي `$SUPAX_HOME/bin`)، وقد أضافه المثبّت إلى `PATH`:

| المصدر | الأمر |
|---|---|
| حزمة محلية | `supax install --path <دليل>` |
| مستودع git | `supax install --git <رابط> [<الاسم>] [--tag <وسم> \| --branch <فرع> \| --rev <التزام>]`، وبلا اسم يؤخذ آخر جزء من الرابط (`…/tool.git` ← `tool`) |
| فهرس الحزم | `supax install <الاسم>[@<متطلب>]`، وبلا متطلب يأخذ أحدث إصدار |

- حزمة git أو الفهرس تُجلب ويُتحقق منها كأي اعتمادية (المخبأ نفسه والبصمة نفسها)، ثم تُنسخ إلى دليل مؤقت وتُبنى فيه ويُحذف الدليل. ولا يُشترط فيها `[lib]` كما يُشترط في الاعتمادية. أما حزمة `--path` فتُبنى في مكانها، في `build/` الخاص بها.
- يسجّل `~/.supax/installed.toml` كل برنامج مثبت مع حزمته وإصدارها ومصدرها، ويعرضه `supax install --list`.
- تثبيت الحزمة مرة أخرى يستبدل برامجها. ولا يكتب سوباكس فوق ملف ثبّتته حزمة أخرى، أو ملف لم يثبّته هو، إلا مع `--force`. ولا يثبّت أبدا برنامجا باسم `supax` أو `sultanc`.
- يحذف `supax uninstall <الحزمة>` برامج تلك الحزمة، ومع `--bin <الاسم>` برنامجا واحدا.
- تُبنى البرامج لهذا الجهاز، ويُرفض `--target`.

## مساحات العمل

عدة حزم في مستودع واحد يجمعها ملف `Supax.lock` واحد في الجذر، كما في Cargo:

<div dir="ltr">

```toml
# Supax.toml في الجذر
[workspace]
members = ["app", "libs/*"]    # "x/*" = كل مجلد تحت x فيه Supax.toml
exclude = ["libs/old"]         # اختياري
```

</div>

| مكان التشغيل | ما تعمل عليه `build` و`check` و`test` | `run` و`add` و`remove` و`metadata` |
|---|---|---|
| داخل عضو | ذلك العضو | ذلك العضو |
| جذر بلا `[package]` | كل الأعضاء (وتُفحص المكتبات) | تحتاج `-p <الاسم>` |
| جذر فيه `[package]` | الحزمة الجذر | الحزمة الجذر |
| أي مكان مع `-p <الاسم>` | ذلك العضو | ذلك العضو |

أما `fetch` و`update` و`verify` و`tree` فتشمل مساحة العمل كلها دائما. وتعمل الاعتماديات المسارية بين الأعضاء كالمعتاد، ويأخذ كل الأعضاء الإصدار نفسه من الاعتمادية المشتركة. والحزمة الموجودة داخل مجلد المساحة وليست في `members` خطأ، إلا إن كانت في `exclude`. ويشترك كل الأعضاء في `build/` واحد في جذر المساحة: البرامج في `build/bin/`، ويحذفه `supax clean` من أي مكان في المساحة.

## الاختبارات

الاختبار دالة موسومة بـ `@@اختبار` (أو `@@test`)، بلا معاملات، ولا ترجع شيئا أو ترجع `نتيجة عدد, فشل`. ويشغّل `supax test` بهذا الترتيب:

| الهدف | الملف | لاختياره وحده |
|---|---|---|
| lib | ملف جذر المكتبة: `[lib] path` إن كان ملفا، وإلا `<جذر المصدر>/<اسم الحزمة>.sn` | `--lib` |
| bin | `src/main.sn` وكل `src/bin/<الاسم>.sn` | `--bin <الاسم>` |
| test | كل `tests/<الاسم>.sn`، وهو برنامج مستقل يستورد المكتبة باسمها، ويستطيع أن يستورد `[dependencies]` الحزمة و`[dev-dependencies]` أيضا | `--test <الاسم>` |

يجد المترجم الاختبارات في الملف وكل ما يستورده، فينبغي أن يستورد ملف جذر المكتبة وحداتها. وفي حزمة لها `[lib]` لا يشغّل البرنامج إلا اختبارات ملفه، فتُشغَّل اختبارات المكتبة مرة واحدة. وإذا فشل هدف توقف التشغيل وطُبع الخيار الذي يعيده وحده، ومع `--no-fail-fast` تُشغَّل الأهداف كلها أولا. ويسرد `--list` الاختبارات دون تشغيلها، وما بعد `--` يُمرَّر إلى `sultanc test` كما هو.

## المخبأ

تُحفظ المستودعات المجلوبة في `~/.supax/git` (أو `$SUPAX_HOME/git`). لكل مستودع ملف قفل، فلا تكتب عمليتا سوباكس في المستودع نفسه معا: تطبع الثانية `ينتظر` وتنتظر. ويحذف `supax cache clean` المخبأ، لكنه يرفض ما دامت عملية سوباكس أخرى تستخدمه، ويُجلب ما يلزم من جديد في البناء التالي.

## الأمان

- لا يشغّل سوباكس شيئا مصدره حزمة مجلوبة: لا نصوص بناء، ولا خطافات git، ولا مرشحات، ولا fsmonitor، ولا نقل `ext::`.
- يتجاهل السحبُ إلى المخبأ إعداداتِ git الخاصة بالنظام والمستخدم، ولا ينشئ وصلات رمزية.
- كل نسخة في المخبأ للقراءة فقط، ولها بصمة SHA-256 تُفحص قبل كل استخدام، وتُقارن بالبصمة المسجلة في `Supax.lock`.
- الاعتمادية المسارية داخل حزمة git لا تخرج من مستودعها.
- تُرفض الأسماء التي تحوي محارف اتجاه خفية أو محارف صفرية العرض، وكذلك الأسماء التي تصير اسما واحدا بعد تطبيع الهوية (حذف التطويلة، وتوحيد آ وأ وإ إلى ا) وهي تشير إلى حزم مختلفة.

| المجلد | محتواه |
|---|---|
| `src/main.sn` | نقطة البداية |

| `src/project/` | `new` و`init`، وتعديل البيان، و`migrate` |
| `src/manifest/` | قراءة `Supax.toml` و`[workspace]` وقراءة TOML |
| `src/resolve/` | نموذج المخطط، والحل، والفحوص، و`Supax.lock`، وخريطة الاعتماديات، والشجرة |
| `src/registry/` | متطلبات الإصدار وفهرس الحزم |
| `src/source/` | مصادر git |
| `src/cache/` | المخبأ والبصمات |
| `src/build/` | تشغيل المترجم، وبرامج المشروع |

| `tests/run.sh` | الاختبارات |

| `tools/` | سكربتات التثبيت (`install.sh` و`install.ps1`) |

## التثبيت

<div dir="ltr">

```sh
tools/install.sh ../sultanc      # بعد بناء المترجم في ../sultanc
```

</div>

وعلى ويندوز (PowerShell، ولم يُجرَّب بعد على جهاز ويندوز):

<div dir="ltr">

```powershell
powershell -ExecutionPolicy Bypass -File tools\install.ps1 -Checkout ..\sultanc
```

</div>

يثبت في `%USERPROFILE%\.supax` ويضيف `.supax\bin` إلى `PATH` الخاص بالمستخدم، ولتخطي ذلك مرر `-NoModifyPath`.

يثبت السكربت `sultanc` و`supax` في `~/.supax/bin`، والمكتبة القياسية في `~/.supax/lib/sultanc/library`، ويضيف `~/.supax/bin` إلى `PATH` تلقائيا في ملفات الصدفة (`~/.zshenv` و`~/.profile` و`~/.bashrc`)، فيكفي بعده فتح نافذة طرفية جديدة. ولتخطي ذلك مرر `--no-modify-path`. ويبحث سوباكس عن المترجم بهذا الترتيب: `SULTANC`، ثم بجانب سوباكس نفسه، ثم `~/.supax/bin`، ثم `PATH`.

## البناء والاختبار

<div dir="ltr">

```sh
mkdir -p build/bin
sultanc --package-graph=bootstrap/package-graph.toml src/main.sn -o build/bin/supax   # البناء الأول (المترجم الأقدم: بلا --package-graph)
build/bin/supax build                      # بعدها يبني سوباكس نفسه
SULTANC=sultanc bash tests/run.sh
```

</div>

يحتاج سوباكس إلى `git` في `PATH`، وإلى مترجم السلطان من 2026-11-16 أو أحدث، من `SULTANC` أو من `PATH`.

</div>
