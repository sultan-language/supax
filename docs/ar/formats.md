# صيغ ملفات سوباكس

## الاعتماديات في `Supax.toml`

<div dir="ltr">

```toml
[dependencies]
mathx = "1.2"                                   # من فهرس الحزم
color = { version = "~0.4" }                    # الشيء نفسه بصيغة جدول
json = { git = "https://github.com/someone/sn-json", tag = "v1.2.0" }
http = { git = "https://github.com/someone/sn-http", branch = "main" }
base = { git = "https://github.com/someone/sn-base", rev = "3f9c2e1" }
tool = { git = "https://github.com/someone/sn-tool" }
log  = { path = "../log" }
```

</div>

| الحقل | معناه |
|---|---|
| `version` | متطلب إصدار يُحل عبر فهرس الحزم. يُذكر واحد فقط من `version` و`path` و`git` |
| `path` | حزمة محلية، مسارها نسبي إلى هذا البيان |
| `git` | رابط بإحدى الصيغ: `https://` أو `http://` أو `ssh://` أو `file://` أو `user@host:path` |
| `tag` و`branch` و`rev` | واحد منها على الأكثر، فإن لم يُذكر أيٌّ منها استُخدم الفرع الافتراضي للمستودع. وقيمة `rev` من 7 إلى 64 محرفا ست عشريا. |

القواعد:

- يجب أن يطابق مفتاح اعتمادية git اسمَ الحزمة في `[package].name` أو إحدى تهجئاتها في `[package.names]`.
- يجب أن تعلن كل اعتمادية الجدول `[lib]`.
- يُسمح بالتزام واحد لكل مستودع في المخطط كله، فإن وصل طلبان إلى التزامين مختلفين فذلك تعارض.
- يُرفض الحقل `[package].build`، لأن سوباكس لا يشغّل شيفرة الحزم أبدا.
- يُسمح بإصدار واحد لكل فئة توافق من حزمة الفهرس (`1.x` و`0.3.x` و`0.0.4`)، كما في Cargo: فيمكن أن يعيش `1.x` لمستورد و`2.x` لآخر معا. أما متطلبان من الفئة نفسها لا يلتقيان على إصدار فتعارض.

### متطلبات الإصدار

القواعد نفسها التي يتبعها Cargo:

| المتطلب | ما يسمح به |
|---|---|
| `"1.2.3"` أو `"^1.2.3"` | `>=1.2.3, <2.0.0` |
| `"^0.2.3"` | `>=0.2.3, <0.3.0` |
| `"^0.0.3"` | `>=0.0.3, <0.0.4` |
| `"1.2"` | `>=1.2.0, <2.0.0` |
| `"~1.2.3"` | `>=1.2.3, <1.3.0` |
| `"=1.2.3"` | `1.2.3` وحده |
| `">=1.2, <1.5"` | كل المقارنات معا |
| `"*"` و`"1.*"` و`"1.2.*"` | محارف بدل |

لا يُختار إصدار تجريبي مثل `1.5.0-beta.1` إلا إذا ذكر المتطلب نفسه إصدارا تجريبيا بالأرقام الثلاثة نفسها. ولا يُختار إصدار مسحوب (yanked) لقفل جديد، لكن القفل الذي يحويه من قبل يبقى صالحا.

## فهرس الحزم

الفهرس مستودع git فيه ملف لكل حزمة. الافتراضي `https://github.com/sultan-language/index`، ويوجّه المتغير `SUPAX_INDEX` سوباكس إلى فهرس آخر (أي رابط git، ومنه `file://`). لا يستضيف الفهرس الشيفرة، بل يشير كل إصدار إلى مستودع git والتزام وبصمة محتوى.

لا يحوي جذر المستودع إلا `README.md` و`config.toml` (فيه `version = 1`، رقم الصيغة) والمجلد `packages/`. ومسار الملف داخل `packages/`، من الاسم بعد تطبيع الهوية وتصغير أحرف ASCII (ترتيب Cargo نفسه):

| الاسم | المسار |
|---|---|
| محرف واحد | `packages/1/<الاسم>.toml` |
| محرفان | `packages/2/<الاسم>.toml` |
| ثلاثة محارف | `packages/3/<المحرف الأول>/<الاسم>.toml` |
| أربعة فأكثر | `packages/<المحرفان 1–2>/<المحرفان 3–4>/<الاسم>.toml` |
| غير ASCII (العربية وغيرها) | `packages/hash/<أول محرفين من البصمة>/<sha256 الاسم>.toml` |

وإن كان `version` في `config.toml` أحدث مما يعرفه سوباكس توقف وطلب تحديثه.

تستعمل الأسماء غير ASCII البصمة لتبقى أسماء الملفات في الفهرس كلها ASCII، لأن macOS يخزن بعض الحروف العربية (أ وإ وآ) مفككة، وهذا يفسد مسارات git.

<div dir="ltr">

```toml
name = "mathx"

[[versions]]
version = "1.2.0"
git = "https://github.com/someone/mathx"
commit = "d5921a779bc910a23dad23714369f718edbb2540"
checksum = "sha256:ecfbacdd291dd749cdbd798543f204e8293c87bcfda58621aa22c78d1755d5f5"

[[versions]]
version = "1.4.0"
git = "https://github.com/someone/mathx"
commit = "…"
checksum = "sha256:…"
yanked = true
```

</div>

يتحقق سوباكس من أن المحتوى المجلوب يطابق `checksum`، ومن أن `version` في `Supax.toml` عند ذلك الالتزام يطابق الفهرس. ويُجلب الفهرس مرة واحدة في كل أمر، وفقط حين لا يحقق `Supax.lock` متطلبا ما.

### إضافة إصدار

يطبع `supax package` (يُشغَّل في مستودع الحزمة) مسار الملف ومدخل `[[versions]]` للالتزام `HEAD`، والبصمة محسوبة كما يحسبها الجلب تماما. ادفع الالتزام، ثم أضف المدخل إلى ذلك الملف في مستودع الفهرس.

## ملف القفل `Supax.lock`

يكتبه سوباكس وحده، ومحتواه واحد مهما كانت لغة الرسائل. تأتي الحزمة الجذر أولا، ثم بقية الحزم مرتبةً بالاسم ثم بالمصدر.

<div dir="ltr">

```toml
# يكتب سوباكس هذا الملف تلقائيا؛ لا تعدّله يدويا. Written by Supax; do not edit by hand.
version = 1

[[package]]
name = "app"
version = "0.1.0"
source = "root"
dependencies = ["json", "log"]

[[package]]
name = "json"
version = "1.2.0"
source = "git"
git = "https://github.com/someone/sn-json"
tag = "v1.2.0"
commit = "2f3a589624b5a839fe13a27ad52323a4e5edabf4"
checksum = "sha256:80d03f48f971bf104d3f3e46eefaba7c54bfa846be17d257847ec7659fe90680"
dependencies = ["base"]

[[package]]
name = "log"
source = "path"
path = "../log"
```

</div>

| الحقل | معناه |
|---|---|
| `source` | `root` أو `path` أو `git` أو `registry` |
| `registry` | لحزم `registry`: رابط الفهرس. ويحفظ المدخل أيضا `git` و`commit` و`checksum`، فلا يقرأ البناءُ المثبَّت الفهرسَ أبدا |
| `commit` | الالتزام الكامل الذي أشار إليه المرجع |
| `checksum` | بصمة محتوى ملفات ذلك الالتزام (انظر أدناه) |
| `subdirectory` | يُذكر للحزمة المسارية الموجودة داخل مستودع git |
| `dependencies` | أسماء الحزم، وتُكتب `"الاسم الإصدار"` إن كان في المخطط إصداران من تلك الحزمة |

وفي مساحة العمل ملف `Supax.lock` واحد في جذرها، وكل عضو فيه مدخل `source = "root"`.

يُعاد استخدام المدخل المثبَّت ما دام مستودعه ومرجعه لم يتغيرا، ومدخل الفهرس ما دام إصداره يحقق المتطلب ورابط الفهرس لم يتغير. ويتجاهل الأمر `supax update` كل التثبيتات، أما `supax update NAME` فيتجاهل تثبيت تلك الحزمة وحدها.

## بصمة المحتوى

البصمة هي `sha256:` متبوعة ببصمة SHA-256 لأسطر مرتبة ترتيبا بايتيا، لكل ملف عادي سطر:

<div dir="ltr">

```
<relative path with />\0<SHA-256 of the file content, hex>\n
```

</div>

أي: المسار النسبي بفواصل `/`، ثم بايت صفري، ثم بصمة SHA-256 لمحتوى الملف بالست عشري، ثم سطر جديد. ويُتجاهل الدليل `.git` في الجذر، وتُرفض الوصلات الرمزية والملفات الخاصة.

## المخبأ

يقع المخبأ في `$SUPAX_HOME/git`، والمسار الافتراضي `~/.supax/git`:

| المسار | محتواه |
|---|---|
| `db/<h16>` | مستودع مجرد (bare) لكل هوية رابط git |
| `checkouts/<h16>/<commit>` | نسخة مسحوبة، ملفاتها للقراءة فقط |
| `checkouts/<h16>/<commit>.sha256` | بصمة تلك النسخة، يُتحقق منها قبل كل استخدام |

`<h16>` هو أول 16 محرفا ست عشريا من بصمة SHA-256 لهوية الرابط. وهوية الرابط هي الرابط نفسه بعد تحويل المخطط والمضيف إلى أحرف صغيرة، وحذف `/` أو `.git` من نهايته.

## مخطط الحزم

تكتبه الأوامر `check` و`build` و`run` في `build/supax/package-graph.toml`، وتمرره إلى المترجم عبر `sultanc --package-graph=<مسار مطلق>`. ويطبعه الأمر `supax metadata`؛ ومع `--output=<ملف>` يكتبه في ذلك الملف، ومع `--relative` تُكتب مساراته نسبةً إلى دليل ذلك الملف. صيغته وحقوله مفصلة في [compiler-integration.md](../compiler-integration.md).

## خريطة الاعتماديات (للمترجم الأقدم)

يكتبها سوباكس في `build/supax/dependency-map.toml` إذا كان في المخطط اعتماديات git، ثم يمررها إلى المترجم عبر `sultanc --dependency-map`. التفاصيل في [compiler-integration.md](../compiler-integration.md).
